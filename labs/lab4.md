# Лабораторная №4. Создание основных компонентов образа: ядро Linux

## Цель работы

Изучить назначение ядра Linux, научиться изменять его конфигурацию и собрать ядро для Lichee RV Dock с заданными параметрами.

## Оборудование и предварительные требования

- рабочий компьютер с ALT Linux;
- не менее 20 Гбайт свободного места для исходного кода и результатов сборки;
- подготовленный архив или каталог исходного кода Linux 6.16;
- установленный кросс-компилятор RISC-V из лабораторной №3;
- права суперпользователя для установки пакетов.

## Ключевые понятия

> [!NOTE]
> **Ядро Linux** — центральная часть операционной системы, которая управляет аппаратными ресурсами и предоставляет системные интерфейсы пользовательским программам.

Само ядро не является полноценной операционной системой. Рабочую среду образуют ядро, системные библиотеки, утилиты и пользовательские приложения.

Основные задачи ядра:

- управление процессором, памятью и устройствами;
- обеспечение безопасности и разграничение прав;
- реализация сетевых протоколов;
- управление файловыми системами и операциями ввода-вывода.

> [!NOTE]
> **Конфигурация ядра** — набор параметров в файле `.config`, который определяет включаемые подсистемы, драйверы и режимы их сборки.

Сборка ядра из исходного кода включает компиляцию и компоновку ядра и выбранных модулей на основе этой конфигурации.

> [!NOTE]
> **PREEMPT_RT** — режим вытеснения ядра, уменьшающий задержки обработки событий и повышающий предсказуемость времени реакции системы.

В современных версиях Linux поддержка PREEMPT_RT входит в основное дерево исходного кода. Это параметр конфигурации ядра, а не отдельный загружаемый модуль.

## Порядок выполнения

### Установка зависимостей

Проверьте свободное место, доступную память, число процессоров и необходимые инструменты:

```bash
df -h "$HOME"
free -h
nproc
command -v make riscv64-linux-gnu-gcc bc flex bison dtc
```

Если зависимости отсутствуют и доступны в уже настроенных репозиториях, установите их:

```bash
apt-get install wget build-essential bc flex bison libncurses-devel openssl libssl-devel dtc
```

Исходный код ядра версии 6.16 доступен в пакете `kernel-source-6.16` из [репозитория Sisyphus](https://www.altlinux.org/%D0%A7%D1%82%D0%BE_%D1%82%D0%B0%D0%BA%D0%BE%D0%B5_Sisyphus%3F). На учебном компьютере рекомендуется использовать заранее установленный пакет или предоставленный преподавателем архив.

> [!CAUTION]
> Не выполняйте `apt-repo rm all` и не переключайте ветку общей рабочей станции ради одной лабораторной. Если пакет отсутствует, используйте подготовленный преподавателем архив, контейнер или локальный репозиторий.

```bash
apt-get install kernel-source-6.16
```

Архив исходного кода будет установлен в `/usr/src/kernel/sources/kernel-source-6.16.tar`. Распакуйте его в отдельный каталог и перейдите в корень полученного дерева исходного кода:

```bash
mkdir -p ~/kernel-build
tar -xf /usr/src/kernel/sources/kernel-source-6.16.tar -C ~/kernel-build
```

Определите имя созданного архивом каталога. Задайте пути к исходникам и отдельному каталогу результатов, подставив фактическое имя дерева:

```bash
KERNEL_SRC="$HOME/kernel-build/имя-каталога-исходников"
BUILD_DIR="$HOME/kernel-out-6.16"
mkdir -p "$BUILD_DIR"
```

> [!WARNING]
> Не запускайте `make mrproper` в дереве, где находятся нужные `.config` или результаты предыдущей сборки: эта цель удаляет их. Если внешняя сборка сообщает, что исходное дерево не очищено, используйте свежую распаковку архива либо отдельную копию и очищайте только её командой `make ARCH=riscv mrproper`.

### Создание базовой конфигурации

Создайте стандартную конфигурацию для архитектуры RISC-V:

```bash
make -C "$KERNEL_SRC" O="$BUILD_DIR" \
    ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- defconfig
cp "$BUILD_DIR/.config" "$BUILD_DIR/.config.defconfig"
```

Параметры команды имеют следующее назначение:

- `ARCH=riscv` выбирает целевую архитектуру и соответствующий каталог `arch/riscv/`;
- `CROSS_COMPILE=riscv64-linux-gnu-` задаёт префикс инструментов кросс-компиляции;
- `O="$BUILD_DIR"` отделяет создаваемые файлы от исходного кода;
- `defconfig` создаёт базовый файл `.config` из `arch/riscv/configs/defconfig`.

Базовая конфигурация включает основные возможности RISC-V, но не гарантирует наличие всех параметров, необходимых конкретной плате.

### Изменение конфигурации

Откройте интерактивный интерфейс настройки для выбранной архитектуры:

```bash
make -C "$KERNEL_SRC" O="$BUILD_DIR" \
    ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- menuconfig
```

В `menuconfig` используйте клавиши со стрелками для навигации, `Enter` для перехода, `Y` для включения параметра в ядро, `N` для выключения и `M` для сборки в виде модуля. Клавиша `/` открывает поиск параметров и показывает их расположение и зависимости.

Найдите параметр `PREEMPT_RT` через поиск:

![Поиск параметра PREEMPT_RT в menuconfig](../pictures/search_in_menuconfig.png)

Результат поиска показывает путь к параметру, его текущее значение и зависимости. Число слева от найденного пути позволяет быстро перейти к доступной части дерева настроек.

Для показанной конфигурации включите `EXPERT`, убедитесь, что `ARCH_SUPPORTS_RT` доступен, а `COMPILE_TEST` отключён. Затем выберите режим полного вытеснения реального времени `PREEMPT_RT`.

Кроме того, проверьте поддержку семейства SoC Allwinner D1 (`ARCH_SUNXI`). Для встроенной поддержки Wi-Fi последовательно включите `CFG80211`, `MAC80211`, семейство `RTW88` и драйвер `RTW88_8723DS` клавишей `Y`. В качестве дополнительного согласованного параметра можно включить `MAGIC_SYSRQ`. Сохраните изменения в `.config`.

Нормализуйте конфигурацию и проверьте целевые символы:

```bash
make -C "$KERNEL_SRC" O="$BUILD_DIR" \
    ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- olddefconfig
grep -E '^CONFIG_(PREEMPT_RT|ARCH_SUNXI|RTW88_8723DS|MAGIC_SYSRQ)=' \
    "$BUILD_DIR/.config"
```

> [!WARNING]
> Строка, вручную добавленная в `.config`, не гарантирует включение функции. Если зависимости не выполнены, `olddefconfig` удалит или изменит её. Для `RTW88_8723DS` недостаточно одного `MMC`: также нужны беспроводная подсистема, `MAC80211` и родительский драйвер `RTW88`.

> [!TIP]
> **Проверка конфигурации.** После выхода из `menuconfig` найдите выбранные параметры в `.config`. Включённые в ядро параметры имеют вид `CONFIG_ИМЯ=y`, а модульные — `CONFIG_ИМЯ=m`.

Зафиксируйте отличия от базовой конфигурации:

```bash
diff -u "$BUILD_DIR/.config.defconfig" "$BUILD_DIR/.config" \
    > "$BUILD_DIR/kernel-config.diff"
make -C "$KERNEL_SRC" O="$BUILD_DIR" \
    ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- savedefconfig
```

Команда `diff` возвращает статус 1, если различия найдены; в данном случае это ожидаемо. Цель `savedefconfig` создаёт в каталоге сборки сокращённый файл `defconfig`, содержащий отклонения от значений Kconfig по умолчанию.

### Сборка ядра

Выберите разумное число параллельных заданий с учётом доступной RAM и правил общего компьютера. Запустите сборку с журналированием и измерением времени:

```bash
JOBS=4
/usr/bin/time -v -o "$BUILD_DIR/kernel-build.time" \
    make -C "$KERNEL_SRC" O="$BUILD_DIR" \
    ARCH=riscv CROSS_COMPILE=riscv64-linux-gnu- -j"$JOBS" \
    > "$BUILD_DIR/kernel-build.log" 2>&1
```

Generic RISC-V `defconfig` включает драйверы для разных платформ, поэтому полная чистая сборка может занимать десятки минут. Не запускайте неограниченное число заданий `-j` и не считайте длительное отсутствие вывода признаком зависания: наблюдайте журнал и загрузку системы.

> [!TIP]
> **Ожидаемый результат.** После успешной сборки файл ядра находится в `arch/riscv/boot/Image`, его сжатый вариант — в `arch/riscv/boot/Image.gz`, а DTB платы — в `arch/riscv/boot/dts/allwinner/sun20i-d1-lichee-rv-dock.dtb`.

Проверьте тип, архитектуру, размер и контрольные суммы результатов:

```bash
file "$BUILD_DIR/arch/riscv/boot/Image"
file "$BUILD_DIR/arch/riscv/boot/dts/allwinner/sun20i-d1-lichee-rv-dock.dtb"
riscv64-linux-gnu-readelf -h "$BUILD_DIR/vmlinux"
sha256sum "$BUILD_DIR/arch/riscv/boot/Image" \
    "$BUILD_DIR/arch/riscv/boot/dts/allwinner/sun20i-d1-lichee-rv-dock.dtb"
```

Сохраните для следующих лабораторных работ перечисленные файлы из `$BUILD_DIR`:

- `arch/riscv/boot/Image`;
- файл `.config` из каталога сборки;
- `arch/riscv/boot/dts/allwinner/sun20i-d1-lichee-rv-dock.dtb`;
- файлы `defconfig`, `kernel-config.diff`, `kernel-build.log` и `kernel-build.time`.

> [!WARNING]
> Не удаляйте дерево сборки и перечисленные результаты после завершения работы. Ядро, конфигурация и DTB потребуются при подготовке загрузочного носителя. Не заменяйте рабочие `Image` или DTB на microSD-карте в этой лабораторной.

## Задание

1. Установите или проверьте зависимости для сборки ядра.
2. Получите и распакуйте исходный код ядра.
3. Создайте стандартную конфигурацию для архитектуры RISC-V и сохраните её копию.
4. Включите режим `PREEMPT_RT` по примеру из подготовительного материала.
5. В разделе выбора SoC включите поддержку семейства Allwinner D1.
6. Включите поддержку Wi-Fi-модуля `RTW88_8723DS`.
7. Добавьте один согласованный с преподавателем параметр, не дублирующий выбранные параметры той же подгруппы.
8. Зафиксируйте различия между изменённой и стандартной конфигурациями.
9. Нормализуйте конфигурацию через `olddefconfig` и создайте сокращённый `defconfig`.
10. Соберите ядро с полученной конфигурацией, сохранив журнал и время сборки.
11. Проверьте тип, архитектуру и контрольные суммы ядра и DTB.
12. Сохраните конфигурацию, ядро, DTB, файлы различий и журнал для дальнейших лабораторных работ.
13. Продемонстрируйте преподавателю конфигурацию и результаты успешной сборки.

## Дополнительные задания

### Вариант 1. Атлас артефактов ядра

Найдите в собственном каталоге сборки `.config`, `Image`, DTB платы и один файл модуля `.ko`. Для каждого объекта укажите назначение, этап использования, размер и способ проверки. Выполните `file` для всех объектов и `riscv64-linux-gnu-readelf -h` для `vmlinux` и модуля. Объясните, почему DTB не является исполняемым ELF-файлом.

### Вариант 2. Карта зависимостей Kconfig

Для `PREEMPT_RT`, `ARCH_SUNXI` и `RTW88_8723DS` найдите определения в Kconfig и составьте таблицу «тип — `depends on` — `select` — назначение — итоговое значение». Затем в копии конфигурации добавьте `CONFIG_PREEMPT_RT=y`, оставив `CONFIG_EXPERT` выключенным, выполните `olddefconfig` и объясните исчезновение невозможной комбинации. Не проводите опыт на единственной сохранённой конфигурации.

### Вариант 3. Полная и сокращённая конфигурации

Сравните число строк и назначение файлов `.config`, `.config.defconfig`, `defconfig` после `savedefconfig` и `kernel-config.diff`:

```bash
wc -l "$BUILD_DIR/.config" "$BUILD_DIR/.config.defconfig" \
    "$BUILD_DIR/defconfig" "$BUILD_DIR/kernel-config.diff"
"$KERNEL_SRC/scripts/diffconfig" \
    "$BUILD_DIR/.config.defconfig" "$BUILD_DIR/.config"
```

Объясните, какой файл фиксирует точное состояние всех символов, какой удобнее для переноса намерений между версиями, а какой показывает изменения относительно выбранной базы.

### Вариант 4. Встроенный драйвер или модуль

В отдельной копии каталога сборки измените `RTW88_8723DS` с `y` на `m`, выполните `olddefconfig` и согласованную инкрементальную сборку. Найдите `rtw88_8723ds.ko` и его зависимости, проверьте их архитектуру через `file`. Сравните последствия `y` и `m` для загрузки Wi-Fi до монтирования корневой файловой системы. Не устанавливайте экспериментальные модули в работающую систему платы.

### Вариант 5. Внешнее дерево сборки

Докажите разделение исходников и результатов при использовании `O="$BUILD_DIR"`: `.config`, `vmlinux`, объектные файлы и журналы должны находиться в каталоге сборки, а не в чистом дереве исходников. Воспроизведите на временной копии сообщение `The source tree is not clean`, затем безопасно восстановитесь с помощью свежей копии или `make ARCH=riscv mrproper`, предварительно убедившись, что в ней нет нужных результатов.

### Вариант 6. Чистая и инкрементальная сборки

Сравните полную сборку после создания конфигурации и повторный запуск той же команды без изменений. Для обоих запусков зафиксируйте команду, число заданий, реальное время, максимальный объём RAM по `/usr/bin/time -v`, размер каталога сборки и итоговый SHA-256 `Image`. Объясните ускорение, но не сравнивайте результаты, полученные при разном числе заданий или существенно разной фоновой нагрузке.
