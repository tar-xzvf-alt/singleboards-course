# Лабораторная №6. Подготовка носителя и запись образа на носитель.

## Цель работы

Освоить процесс подготовки загрузочного носителя для одноплатного компьютера, используя готовые компоненты образа Linux.

## Подготовительный материал

## Разбивка SD-карты

После подготовки компонентов можно описать процесс записи образа на sd-карту, заодно заново перечислив все необходимое.

Итак, начнем с того, что предварительно нам нужно будет изменить разбивку sd-карты, если такая присутствует.

::: attention
Команды `dd`, `fdisk` и `mkfs` безвозвратно уничтожают данные на выбранном устройстве. Перед каждым запуском проверьте модель и размер карты, например командой `lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS`, убедитесь, что `/dev/sdX` — именно SD-карта, и размонтируйте все её разделы. Для второго раздела примите предлагаемый `fdisk` последний сектор, чтобы занять всё оставшееся пространство независимо от фактической ёмкости карты.
:::

Для этого предварительно затрем начало SD-карты нулями, при чем с запасом, чтобы гарантированно уничтожить таблицу разделов(10 МБ для этого вполне достаточно).

```
$ sudo dd if=/dev/zero of=/dev/sdX bs=1M count=10
```

Продолжим. Запустим утилиту fdisk и зададим разбиение на 2 раздела. После чего, я поясню наглядно, чего мы тем самым добились.

```
$ sudo fdisk /dev/sdX
```

```
o               # создаем новую DOS таблицу разделов
n               # новый раздел
p               # primary
1               # номер раздела
2048            # начальный сектор
+100M           # размер 100MB
n               # новый раздел
p               # primary
2               # номер раздела
[Enter]         # начать сразу после первого раздела
[Enter]         # использовать всё оставшееся пространство
w               # записать изменения и выйти
```

Далее нужно отформатировать созданные разделы в файловую систему(vfat) и файловую системы ext4 с соответсвующими метками. Выбор файловых систем обусловлен тем, что u-boot "из коробки" работает с файловой системой vfat, а ext4 просто достаточно надежная и подходит для размещения на нем rootfs.

::: additional
VFAT выбран для раздела BOOT из-за простой и широко поддерживаемой U-Boot структуры, а ext4 — для ROOTFS, поскольку поддерживает права доступа, символические ссылки и другие возможности Linux. В другой загрузочной конфигурации U-Boot может читать BOOT и с ext4, но в этой работе используйте указанную схему.
:::

```
$ sudo mkfs.vfat -n BOOT /dev/sdX1

$ sudo mkfs.ext4 -L ROOTFS /dev/sdX2
```

Готово!

Можно проверить результат

```
$ sudo fdisk -l /dev/sdX
```

## Запись компонентов образа

Представим схематично, как будет выглядеть финальное пространство sd-карточки. В нашем случае, она на 32 Гб. 

![Схема разбивки SD-карты на разделы BOOT и ROOTFS](../pictures/разбивка_карты.png){width=72%}

Теперь нужно пояснить, что и куда будет записано. 

### Запись u-boot

Для начала, запишем u-boot в начало карты командой

::: attention
Ещё раз проверьте модель и размер `/dev/sdX`: в этой команде указывается всё устройство без номера раздела, и ошибка уничтожит данные на другом диске. Разделы карты должны оставаться размонтированными. Путь к файлу U-Boot заключайте в кавычки, особенно если он содержит пробелы.
:::

```
$ sudo dd if="/путь/до/загрузчика/lichee rv dock/u-boot-sunxi-with-spl.bin" of=/dev/sdX bs=1k seek=8
```

Таким образом, загрузчик будет записан в область до первого раздела, откуда BootROM процессора сможет его загрузить. Параметр *seek* пропускает 8 килобайт от начала пространства карты. Синим на картинке изображены пропущенные 8 КБ, а красным — пространство, занимаемое загрузчиком.

::: additional
Смещение 8 КБ (`bs=1k seek=8`) задано схемой загрузки Allwinner: оно оставляет начальные служебные секторы и размещает SPL/U-Boot там, где его ищет BootROM. Рисунок является упрощённым и выполнен не в масштабе: таблица MBR находится в первом секторе карты, U-Boot начинается со смещения 8 КБ, а первый раздел — с сектора 2048; загрузчик должен помещаться в области до первого раздела.
:::

### Раздел BOOT

Для начала необходимо заполнить всем необходимым раздел BOOT

::: attention
Раздел должен иметь метку `BOOT`, а конфигурация загрузчика — находиться строго по пути `BOOT/extlinux/extlinux.conf`. Иное имя каталога или размещение файла в корне BOOT не позволит U-Boot найти конфигурацию.
:::

Для начала, положим на BOOT самое главное — ядро(или сжатое ядро .gz) с именем Image(или любым другим). **Перейдем в склонированную директорию** и выполним

```
$ cp kernels/Image_6.16_wifi_rt /путь/до/BOOT/Image
```

Далее, положим туда же скомпилированный файл device tree, полученный в результате выполнения лабораторной №4.

```
$ cp dts_and_dtb/sun20i-d1-lichee-rv-dock.dtb /путь/до/BOOT/
```

Далее, нужно взять полученный в результате выполнения лабораторной №5 конфигурационный файл для загрузчика, который сообщит ему, какое ядро запускать, с каким device tree и какими параметрами. Важно разместить этот файл в директории с одноименным названием *extlinux*.

```
$ mkdir -p /run/media/username/BOOT/extlinux
$ cp extlinux.conf /run/media/username/BOOT/extlinux/extlinux.conf
```


### Раздел ROOTFS

На этот раздел нам нужно распаковать содержимое, которое полностью соответствует заданной метке раздела. 

Распакуем архив на раздел ROOTFS:

```
$ sudo tar -xJpf /путь/до/rootfs.tar.xz -C  /путь/до_раздела/ROOTFS/
```

Готово! Можно пробовать вставлять SD-карту в разъём одноплатника и наблюдать за процессом запуска через UART.

::: attention
Перед извлечением кардридера выполните `sync`, дождитесь завершения команды и размонтируйте разделы BOOT и ROOTFS. Подключайте UART только при выключенном питании платы, используйте логические уровни 3,3 В и обязательно соедините GND платы и преобразователя; уровень 5 В может повредить плату.
:::
