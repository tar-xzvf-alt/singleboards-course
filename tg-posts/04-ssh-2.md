**SSH — ключи, scp и безопасность. Часть 2/2**

Парольный вход в 2026 — моветон. Поднимаем аутентификацию по ключам:

Создаём нового пользователя (root только для чрезвычайных ситуаций):
```
useradd dev
passwd dev
```

На ПК генерим ключ:
```
ssh-keygen -t ed25519
```

Копируем публичный ключ на плату:
```
ssh-copy-id dev@192.168.1.50
```

Теперь заходим без пароля. После этого в `/etc/openssh/sshd_config` отключаем:
- `PermitRootLogin no` — root по SSH не ходит
- `PasswordAuthentication no` — только ключи

Перезапускаем sshd. Теперь пробраться на плату можно только с твоим приватным ключом.

Бонус: `scp` для передачи файлов. Скомпилировал программу на ПК — закинул на плату:
```
scp program dev@192.168.1.50:/home/dev/
```

Обратно — точно так же. Удобно таскать скомпилированные бинарники, конфиги, Device Tree.

После настройки сети UART обычно остаётся аварийным входом для загрузчика и ядра. Всё повседневное удобнее делать по SSH: плата лежит на столе, подключена только к питанию, а ты работаешь с ней как с удалённым сервером.

Кстати: если плата перестала отвечать по SSH, а UART молчит — проверь питание. 90% проблем на стенде решаются переподключением Type-C кабеля.
