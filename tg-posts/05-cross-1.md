**Кросс-компиляция: собираем на ПК, бежит на плате. Часть 1/2**

У тебя мощный x86_64 десктоп. У платы — одно RISC-V ядро на 1 ГГц и 256 МБ RAM. Компилировать ядро прямо на плате можно, но это часы. Хочется иначе.

Кросс-компиляция: компилятор на архитектуре A (host) генерирует код для архитектуры B (target). Исходник один и тот же, но на выходе бинарник, который понимает только целевой процессор.

Ставим тулчейн для RISC-V:
```
apt-get install gcc-riscv64-linux-gnu
```

В системе появляется целое семейство утилит с префиксом `riscv64-linux-gnu-`:
- `riscv64-linux-gnu-gcc` — компилятор C
- `riscv64-linux-gnu-g++` — компилятор C++
- `riscv64-linux-gnu-ld` — линковщик
- `riscv64-linux-gnu-objdump` — дизассемблер

Компилируем обычный динамический бинарник:
```
riscv64-linux-gnu-gcc -o hello hello.c
```

Пытаемся запустить на хосте — `Exec format error`. Бинарник для RISC-V, x86 его не понимает. Но мы можем проверить, что он корректный:

```
file hello
```
Выдаст что-то вроде: `ELF 64-bit LSB executable, UCB RISC-V, version 1 (SYSV), dynamically linked...`

Что такое статическая линковка и зачем она нужна — в следующей части.
