**Кросс-компиляция: QEMU и статическая линковка. Часть 2/2**

Проверить RISC-V бинарник без платы можно через QEMU в режиме user-space. Это не полноценная виртуальная машина: QEMU эмулирует инструкции целевого процессора, а системные вызовы переводит в вызовы ядра хоста.

```
riscv64-linux-gnu-gcc -static -o hello hello.c
qemu-riscv64-static ./hello
Hello, world from RISC-V!
```

Бинарник для чужой архитектуры выполняется на твоём x86 как родной.

Дальше — круче. Включаем `binfmt_misc` — механизм ядра, который позволяет регистрировать обработчики для исполняемых файлов по сигнатуре. После настройки любой RISC-V ELF-файл запускается просто по `./program` — без явного вызова QEMU. Система сама дёргает `qemu-riscv64-static` при попытке выполнить файл.

Статическая линковка: флаг `-static` кладёт нужные библиотеки (включая libc) внутрь бинарника. На выходе — один файл, который можно кинуть на плату и запустить, не думая, есть ли там нужные `.so`.

Минус: размер. Плюс: полная автономность. Для прототипирования — самое то. Скопировал через scp, запустил, работает.

В реальных проектах используют динамическую линковку и sysroot (копию корневой ФС целевой архитектуры), чтобы линковаться с правильными версиями библиотек. Но на старте `-static` экономит кучу нервов.
