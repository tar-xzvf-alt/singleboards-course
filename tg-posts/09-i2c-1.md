**I2C: шина, где у каждого есть адрес. Часть 1/2**

SPI быстрый, но у него недостаток: каждому устройству — отдельный CS-пин. Десять датчиков = десять пинов только на селект. Это неэффективно.

I2C решает проблему иначе: два сигнальных провода на всех, идентификация по адресу.

- SDA (Serial Data) — двунаправленная линия данных
- SCL (Serial Clock) — тактовый сигнал, обычно генерируется мастером

Обе линии открытый сток/open-drain: устройства не выдают «единицу» активно, а только тянут линию к земле. Поэтому нужны подтягивающие резисторы к 3.3V. Без них шина превращается в гадание по шуму.

Все устройства висят на этих двух линиях параллельно. Каждое имеет 7-битный адрес (плюс бит направления R/W). Мастер начинает транзакцию: шлёт стартовый бит, затем 7 адресных бит + бит чтения/записи. Все слушают. Отзывается только тот, чей адрес совпал — выставляет ACK (подтверждение), подтягивая SDA к земле. Дальше идёт обмен данными.

Особенность: адрес задан производителем микросхемы. Например, BME280 по умолчанию 0x76 (можно сменить на 0x77, подав HIGH на пин SDO). SSD-1306 — 0x3C. Конфликт адресов — типичная проблема, когда пытаешься повесить два одинаковых датчика на одну шину.

Скорость: стандартный режим 100 кбит/с, быстрый — 400 кбит/с. Намного медленнее SPI, зато экономнее по пинам.
